# Dark Mode Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add system-aware dark mode with manual toggle to the Evenzi coming-soon page by activating the existing `.dark` CSS token infrastructure, completing the missing brand-token overrides, and wiring up `next-themes`.

**Architecture:** `next-themes` applies `.dark` to `<html>` based on `prefers-color-scheme` (default) or manual toggle. Tailwind v4's existing `@custom-variant dark (&:is(.dark *))` picks this up for all `.dark .x` selector overrides. The incomplete `.dark` CSS block is extended with brand token overrides (`--ink`, `--ink-muted`, `--surface`, `--surface-alt`, `--border-soft`). Hardcoded inline radial-gradient decorations in Hero and FeatureTeasers are extracted to named CSS utility classes that each have a `.dark` override.

**Tech Stack:** Next.js 15, React 19, Tailwind v4, `next-themes` (new dependency), lucide-react (Sun/Moon icons already installed)

### Task 2: Create ThemeProvider wrapper

**Files:**
- Create: `app/providers.tsx`

- [ ] **Step 1: Create the file with this exact content**

```tsx
"use client";

import { ThemeProvider as NextThemesProvider } from "next-themes";

export function ThemeProvider({ children }: { children: React.ReactNode }) {
  return (
    <NextThemesProvider attribute="class" defaultTheme="system" enableSystem>
      {children}
    </NextThemesProvider>
  );
}
```

`attribute="class"` tells next-themes to apply the `.dark` class to `<html>`, which is what Tailwind v4's `@custom-variant dark (&:is(.dark *))` requires. `defaultTheme="system"` + `enableSystem` make the page honor `prefers-color-scheme` until the user manually overrides.

### Task 9: Create ThemeToggle component

**Files:**
- Create: `src/components/evenzi/ThemeToggle.tsx`

- [ ] **Step 1: Create the file**

```tsx
"use client";

import { Moon, Sun } from "lucide-react";
import { useTheme } from "next-themes";
import { useEffect, useState } from "react";

export function ThemeToggle() {
  const { resolvedTheme, setTheme } = useTheme();
  const [mounted, setMounted] = useState(false);

  useEffect(() => {
    setMounted(true);
  }, []);

  if (!mounted) {
    return <div className="h-9 w-9" aria-hidden="true" />;
  }

  return (
    <button
      type="button"
      onClick={() => setTheme(resolvedTheme === "dark" ? "light" : "dark")}
      aria-label={resolvedTheme === "dark" ? "Switch to light mode" : "Switch to dark mode"}
      className="inline-flex h-9 w-9 items-center justify-center rounded-full border border-border-soft bg-card/80 text-ink-muted backdrop-blur-sm transition-all duration-300 hover:border-brand-red hover:text-brand-red"
    >
      {resolvedTheme === "dark" ? (
        <Sun className="h-4 w-4" strokeWidth={2} />
      ) : (
        <Moon className="h-4 w-4" strokeWidth={2} />
      )}
    </button>
  );
}
```

The `mounted` guard is required: next-themes resolves the active theme client-side only. Without the guard, the SSR output has `resolvedTheme === undefined`, which renders nothing — then the client hydrates with the actual theme, producing a mismatch warning. The `<div className="h-9 w-9" />` placeholder matches the button size to prevent layout shift.

`resolvedTheme` (not `theme`) is used because `theme` can be `"system"` while `resolvedTheme` is always `"light"` or `"dark"`.
